Display Lines, Precision, and Exponent Range

Evaluate what a calculator reveals, stores, rounds, and overflows before trusting it with engineering-scale quantities.

X: READY   Y: CHECK   Z: UNITS   T: SOURCE

Procedure 2 / six · Julian Voss

01 / Single-Line Displays

I begin the single-line displays review with visibility. I photograph or transcribe exactly what the screen shows after entry, after an operation, and after recall, noting annunciators for mode, exponent, sign, and pending state. The display is an instrument surface, not decoration. If a crucial distinction requires memory or a tiny indicator, I record that human-factor cost beside the nominal digit count.

Next I separate single-line displays from display rounding. A value can be stored with more digits than the screen presents, so I calculate a cancellation-sensitive example and carry the result into a second operation. Changing the display format should not silently change stored data. When documentation is vague, I design paired computations that reveal rounding behavior without pretending that the experiment establishes every detail of the numeric engine.

Range work connects single-line displays to exponent limits. I step powers of ten toward the documented limits, watching for normalized notation, subnormal behavior, underflow to zero, and explicit overflow. Every probe has an expected order of magnitude written first. A dramatic exponent is not a difficult test by itself; the test is whether the calculator communicates the boundary and whether the operator interprets it correctly.

The reporting rule for single-line displays is independent of screen capacity. I round according to input quality, retain guard digits only during calculation, and attach units outside the numeric display. Extra digits may help avoid accumulated roundoff, yet they cannot repair uncertain measurements. Acceptance requires a repeatable normal case, a boundary case, and a documented explanation of what is stored versus what is merely formatted.

Field checklist

  • Write the expected magnitude and units before entry.
  • Record the starting mode and any stored-state assumptions.
  • Repeat a boundary case and an ordinary case.
  • Confirm the result through an independent route.
  • Leave enough notation for another reader to resume.
