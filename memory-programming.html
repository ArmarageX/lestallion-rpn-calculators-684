Registers, Programs, and Verification Routines

Organize stored values and short programs so repeated calculations remain inspectable, reversible, and easy to audit.

X: READY   Y: CHECK   Z: UNITS   T: SOURCE

Procedure 5 / six · Julian Voss

01 / Named Register Map

I assign named register map on paper before storing the first value. Each entry receives a symbol, unit, source, revision, and permitted range. Registers are then addresses in a small controlled data set rather than unlabeled hiding places. This ledger prevents yesterday’s density, angle, or calibration factor from masquerading as today’s input simply because recall produced a familiar-looking number.

The routine linking named register map and branching limits begins with explicit initialization. I clear only the intended state, load a published test vector, and compare every intermediate output with a reference sheet. Storage arithmetic is checked after each accumulation. If a total can survive between jobs, the closeout step records it and restores a known baseline so the next operator does not inherit undocumented history.

Programming around test vectors needs version discipline. I write the algorithm in ordinary notation, list input prompts and output meanings, and preserve at least one normal, boundary, and failure case. Branching is traced in both directions. A compact keystroke program is not self-documenting; its brevity makes an external record more important, especially when labels, comments, or export are limited.

I release a named register map routine only when another person can initialize it, run the test vectors, identify its revision, and verify one result independently. Reset and battery-loss recovery belong in that review. If the program becomes difficult to inspect or compare, I move it to a version-controlled script rather than treating calculator memory as a permanent software repository.

Field checklist

  • Write the expected magnitude and units before entry.
  • Record the starting mode and any stored-state assumptions.
  • Repeat a boundary case and an ordinary case.
  • Confirm the result through an independent route.
  • Leave enough notation for another reader to resume.
